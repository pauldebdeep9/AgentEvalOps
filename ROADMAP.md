### Re-baseline, 2026-10-10 — ADR-0005 (read this first)

- **What changed.** v0.5's headline is no longer "SWE-bench Verified subset on AWS Fargate". ### External review, 2026-10-31 — CI was red for six weeks; teardown race fixed; twelve findings confirmed

- **CI on `main` was red from 2026-09-15 until `9cc2b00` (2026-10-31): 4 of 4 pushes, every test job** (Python 3.10, 3.11, 3.12 and min-deps). One test failed every time — `test_cancellation_of_waiting_sibling_task_still_tears_down`, added in `fa90c0f` — and it passed on macOS only because of thread timing. Nobody looked at the Actions runs, so the whole ADR-0005 re-baseline and the IMDA review were gated locally only. This is W8's "red CI that nobody noticed" pattern again (History, below: two commits then, four pushes and six weeks now). `CLAUDE.md` now requires `gh run watch` after every push and forbids ending a session while CI is red.
- **Fixed (`9cc2b00`): teardown skipped under repeated cancellation.** `LocalOrchestrator._run_task`'s `finally` awaited `asyncio.to_thread(teardown)`. A task cancelled twice — by `asyncio.run`'s shutdown, then by `run()`'s drain loop — had its queued executor job cancelled before a worker thread started it, and the `except Exception` guard cannot see `CancelledError`. `_teardown` (`orchestration/local.py:337`) now submits the job once, waits with `asyncio.wait` (which never cancels it), absorbs each cancellation and re-raises the last one after teardown finishes. A new test holds B's teardown job in the executor queue across a second cancel, so it fails deterministically without the fix (30 of 30 runs on macOS); CI is green on all four jobs at `9cc2b00`. This also settles D5's accepted risk "a second cancellation arriving during `teardown` itself" (`docs/benchmark_adapters.md`), which understated the effect: teardown did not run at all.
- **Open, not fixed: two cancellation gaps, both added to R22's ADR-0006 list.** (1) Cancelling a task while `prepare_environment` is running still leaks the environment: the thread finishes, the handle is never received and teardown never runs — D5's open question on cancelling prepare, now the only cancellation path without cleanup. (2) `_teardown` now waits with no time limit, so a hung teardown would stop Ctrl-C from ending the run and from writing the interrupted bundle. One option: stop waiting after about 30 s, log a warning and re-raise; the thread still finishes and is joined at exit. Not built.

## 4. Critical path (re-baselined 2026-10-10)

These four items, if they slip, move the v0.5 date. Everything else has slack.

**Critical path item 1: ADR-0006 and the runner tool seam (R22–R23).** Every B and E row needs tools that the environment supplies and records. Mitigation: if `LangGraphRunner`'s refactor stalls, v0.5 ships with the mock and OpenAI-family runners on the seam and `LangGraphRunner` documented as toy-only. The seam is critical; runner breadth is not.

## 8. What this roadmap does not promise

If its assumptions hold, v0.5 ships in the week of January 25, 2027. The assumptions: ~12 productive hours a week; IMDA's agent-testing categories do not change shape before R31 (if they do, the catalogue re-maps them — risk 2); one provider account funded by Jan 4; no cloud infrastructure needed.

It does not promise any certification, compliance or accreditation outcome. The evidence pack is evidence, not a verdict (ADR-0005 D10).

It does not promise a public release. The repository stays private through v0.5, and nothing is submitted to JOSS (E7, decided 2026-10-10); v0.5 is released to named partners.

It does not promise that agents score well. A v0.5 whose live run shows a 40% policy-compliance pass rate is a successful release; the platform is what's being demonstrated.

It does not promise that SWE-bench or AWS return on any particular date. Both are frozen, not abandoned (ADR-0005 D3).

If any of these assumptions changes, this document is re-baselined. The roadmap is a tool, not a contract.
