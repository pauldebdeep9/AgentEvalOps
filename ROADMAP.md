### Re-baseline, 2026-10-10 — ADR-0005 (read this first)

- **What changed.** v0.5's headline is no longer "SWE-bench Verified subset on AWS Fargate". - **Open gap, found 2026-08-03: the platform does not distinguish infrastructure failure from agent/evaluation failure — an infra failure during any task currently discards the entire run's results rather than scoring or reporting anything.** Investigated by tracing the actual code path (not just reading it) against the real partial bundle from the 2026-08-03 `OpenAIRunner` live-verification attempt, preserved at `tests/fixtures/bundles/partial-infra-failure-2026-08-03/` (see its README for full provenance). Findings, evidence-first:
  - `core/schemas.py:72` defines `TerminationReason.INFRA_FAILURE`, and it is exercised by exactly one place in the whole codebase: `tests/test_core_schemas.py:94`, an isolated unit test asserting its string value. `grep -rn "INFRA_FAILURE" src/` finds no other hits — no runner, orchestrator, evaluator, or report code ever constructs an `AgentOutput` or trace event carrying it. The vocabulary exists; the behavior doesn't.
  - `core/errors.py`'s `InfrastructureError` docstring states the intended contract plainly: *"Agent-level failures (wrong answer, agent giving up) are NOT this exception — those are captured in `AgentOutput.termination_reason`."* Both runners honor the raise side of that contract correctly (`agents/openai_runner.py:365-366`, `agents/langgraph_runner.py:338-339`: a blanket `except Exception as exc: raise InfrastructureError(...)` around the model API call — this is not 429-specific, it uniformly wraps timeouts, 5xx, network errors, and auth failures alike). But nothing implements the *catch* side of that contract.
  - `orchestration/local.py`'s `LocalOrchestrator.run()` (lines 135-149) only catches `(KeyboardInterrupt, asyncio.CancelledError)` around `asyncio.gather(*futures)`. `InfrastructureError` is neither, so it propagates straight out of `run()` — skipping the per-task result loop, `trace_store.finalize()`, `SimpleScorer().score(...)`, and `policy_checker.check(...)` for **every** task in the run, not just the one that failed. `cli.py`'s `run` command (lines 130-132) only catches it around the top-level `asyncio.run(orchestrator.run())` call — prints `"Infrastructure error: {exc}"` to stderr and exits 1, before `_print_summary()` or `BundleWriter.write()` are ever reached.
  - **Correction to how this was initially framed going into the investigation:** the 2026-08-03 live run did **not** "report 0/2 passed, 0 tokens, $0.00" anywhere — that framing doesn't match the evidence. No `RunSummary` was ever returned, so `_print_summary()` never ran and no bundle beyond a stray `traces.jsonl` (two `agent.plan` events, no cost or terminal events — confirmed against the actual fixture) was ever written. The real defect is more severe than "an outage gets silently scored as failure": it's "an outage during any one task erases evaluation of the *entire* run, with no bundle, no report, and no summary of any kind" — confirmed via `validate-bundle` against the real bundle: `FAIL`, missing `metadata.json`, `config.json`, `evaluations.json`, `policy.json`, `summary.json`, `report.md`, and `manifest.json`.
  - `policy/basic_checker.py`'s `BasicPolicyChecker.check()` (lines 32-85) checks only cost ceiling, tool deny-list, and trace-event count — it never inspects `output.success`, `output.termination_reason`, or whether any tasks were evaluated at all. The other findings in this gap (orchestrator crash-through, report/scorer collapse, the malformed-response third path) are unaffected and remain open.
  - `reports/markdown.py`'s per-task table (lines 65-75) *would* render `infra_failure` correctly in its "Termination" column if an `AgentOutput` ever carried it — the per-row signal isn't designed away. But the report's headline aggregate (`- Tasks: {passed} / {total} passed ({failed} failed, {pass_rate:.0f}%)`, lines 50-53) and `RunSummary.passed_tasks`/`.failed_tasks` make no such distinction; `evaluators/deterministic.py`'s check 1 (`base_passed = output.success and output.termination_reason == COMPLETED`) folds `INFRA_FAILURE` into `passed=False`/`score=0.0` exactly like a genuine wrong answer or `AGENT_ERROR`. A reader trusting the headline number — the one DESIGN.md's regression-comparison use case actually consumes — cannot tell an outage from a bad answer.
  - A **third, quieter** behavior exists alongside the two above: a malformed/unexpected-*shape* API response (not an exception) never raises at all — both runners' `_ParsedResponse.__init__` reads every field via `getattr(obj, attr, default)`, so it silently produces zero-valued fields that typically resolve to `TerminationReason.AGENT_ERROR`, indistinguishable even in the evaluator's notes from a real agent mistake. So 429 is not special and the collapse is not one bug but three related ones: (a) transport/API exceptions → whole-run abort, nothing scored; (b) missing/bad API key (`ConfigurationError`) → same whole-run abort via a separate but equally uncaught path; (c) malformed response shape → silently absorbed as an ordinary agent failure.
  - **Verdict: this is a real defect, not primarily a documentation gap** — though a real documentation gap sits alongside it. The runner-level contract (raise vs. capture) *is* documented and correctly followed. What's undocumented is everything after the raise: `ARCHITECTURE.md` §5 only gestures at this ("if the orchestrator is interrupted (Ctrl-C, OOM, sandbox died) ... best effort to finalize the partial bundle") — language that groups "sandbox died" with `KeyboardInterrupt`, implying infra failures were meant to get the same best-effort-finalize treatment — but the code's actual except-clause never lists `InfrastructureError`. The code doesn't match its own architecture doc's stated intent, and there is no coherent *designed* behavior here to merely document — an accidental crash-through isn't a documented gap waiting for a docstring, it needs new code.

Since `RunSummary`/`EvaluationResult` serialize into `summary.json`/`evaluations.json`, this is a bundle-format change under `ARCHITECTURE.md` §3's `schema_version` rule, not an internal refactor — exactly why it wasn't done in this session.

## 8. What this roadmap does not promise

If its assumptions hold, v0.5 ships in the week of January 4, 2027. The assumptions: ~12 productive hours a week; IMDA's agent-testing categories do not change shape before W31 (if they do, the catalogue re-maps them — risk 2); one provider account funded by Nov 30; no cloud infrastructure needed.

It does not promise any certification, compliance or accreditation outcome. The evidence pack is evidence, not a verdict (ADR-0005 D10).

It does not promise a public release. The repository stays private through v0.5, and nothing is submitted to JOSS (E7, decided 2026-10-10); v0.5 is released to named partners.

It does not promise that agents score well. A v0.5 whose live run shows a 40% policy-compliance pass rate is a successful release; the platform is what's being demonstrated.

It does not promise that SWE-bench or AWS return on any particular date. Both are frozen, not abandoned (ADR-0005 D3).

If any of these assumptions changes, this document is re-baselined. The roadmap is a tool, not a contract.
